# Attribution to Hoursly

Map reconstructed work to live Hoursly client, project, deliverable, Activity and Billing Role records. Attribution explains where work belongs; it does not prove duration, attendance or outcome.

## Ordered evidence

Use the first strong rule that resolves the assignment. Later rules may corroborate it but should not overrule a clearer earlier mapping.

1. An explicit mapping the user gave in this review.
2. The same repository, project key, document, thread or source already mapped on an existing Hoursly entry.
3. A unique ticket key, repository, label, channel or workspace association.
4. An attendee or recipient organisation/domain that maps unambiguously to one client.
5. An exact, unique title or outcome keyword supported by live Hoursly names.
6. Continuation of the same document, thread or workstream as a confidently attributed adjacent fragment.
7. Time adjacency alone. Treat this as weak evidence and ask rather than silently assigning.
8. No supported match. Leave the field unassigned and ask one focused question.

Do not use private attendee or recipient details in the saved description. A client match does not automatically identify the project, deliverable, Activity, Billing Role or billable state; resolve each required field independently.

## Confidence and conflicts

- **Supported:** one high-signal rule or several consistent independent signals point to a unique live record.
- **Needs review:** the evidence is incomplete, keyword-only, based on adjacency, or matches several live records.
- **Conflict:** the user's mapping, an existing Hoursly association and source evidence disagree. Show the named alternatives and hold the write.

Prefer an established user mapping over a new inference unless later evidence shows it is stale. Never create a client, project or deliverable to make a proposal fit. Never infer billability from an external domain or infer a grant/funder association from a person's identity.

## Grouping boundary

Only group short evidence fragments when their entry type and resolved client, project, deliverable/Activity, Billing Role and coherent outcome all agree. A confident project match does not justify combining unrelated work, converting Agent execution into Human time, or moving tokens between records.
